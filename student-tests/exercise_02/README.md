# תרגיל 2: יצירת משחק ומצב פתיחה

## מטרת התרגיל

לאפשר יצירת משחק חדש עבור שניים עד ארבעה שחקנים ולהחזיר מצב משחק מלא שה-UI יכול להציג ללא השלמת מידע בעצמו.

## נקודת הקצה הנדרשת

### `POST /api/game`

גוף הבקשה:

```json
{"player_names": ["Ada", "Linus"]}
```

בקשה תקינה מחזירה `200` ואת `GameState` ישירות, ללא מעטפת נוספת.

## אימות שמות השחקנים

יש לבצע את כל הבדיקות הבאות לפני החלפת המשחק הפעיל:

- מספר השמות הוא 2–4. רשימה של שחקן אחד או חמישה שחקנים מחזירה `422`.
- מסירים רווחים מתחילת כל שם ומסופו.
- שם ריק, או שם שהופך לריק לאחר הסרת רווחים, מחזיר `422`.
- שמות כפולים מחזירים `422`, גם אם ההבדל הוא רק אותיות גדולות/קטנות, למשל `Ada` ו-`ada`.
- כל תגובת `422` כוללת גוף JSON עם המפתח `detail`.

## מבנה `GameState`

האובייקט חייב להכיל בדיוק את שמונת המפתחות הבאים, ללא מפתחות חסרים או נוספים:

- `status`: מציין באיזה שלב נמצא המשחק. משחק חדש מתחיל כ-`active`; בהמשך הוא יוכל לעבור ל-`finished`.
- `current_player_id`: מזהה את השחקן שתורו לפעול כעת. בתחילת המשחק זהו השחקן הראשון, שמזההו `1`.
- `winner_id`: מזהה את השחקן שניצח. כל עוד אין מנצח הערך הוא `null`.
- `available_actions`: מגדיר אילו פעולות השרת מרשה לבצע במצב הנוכחי, וכך ה-UI יודע אילו כפתורים לאפשר. משחק חדש מתחיל עם `["roll"]` בלבד.
- `players`: מחזיק את מצבם העדכני של כל השחקנים, לפי סדר השמות בבקשה.
- `board`: מתאר את 16 המשבצות ואת מצבן, כולל סוג המשבצת ובעלות על נכסים.
- `last_event`: מאפשר ל-UI להציג במהירות את האירוע האחרון שהתרחש. בתחילת המשחק ערכו `Game created. Roll to begin.`.
- `event_log`: שומר את היסטוריית אירועי המשחק לפי הסדר שבו התרחשו. הרשימה מתחילה באירוע יצירת המשחק.

לכל שחקן יש את השדות הבאים:

- `id`: מזהה ייחודי של השחקן, החל מ-1 ובהתאם לסדר השמות בבקשה.
- `name`: השם שיוצג עבור השחקן בממשק ובאירועי המשחק.
- `money`: יתרת הכסף של השחקן, שמתחילה ב-1500 ומשתנה בעקבות קנייה והשפעות משבצות.
- `position`: מזהה המשבצת שעליה השחקן נמצא. כל השחקנים מתחילים במשבצת 0.
- `is_bankrupt`: מציין אם השחקן פשט רגל ואינו יכול להמשיך להשתתף. בתחילת המשחק הערך הוא `false`.
- `owned_tile_ids`: רשימת מזהי הנכסים שבבעלות השחקן. בתחילת המשחק הרשימה ריקה.

## הלוח הנדרש

לכל משבצת יש `id` שמציין את מיקומה במסלול, `name` שמוצג למשתמש ו-`type` שקובע כיצד היא מתנהגת. במשבצת נכס, `price` הוא מחיר הקנייה, `rent` הוא הסכום שישולם לבעלים ו-`owner_id` מזהה את הבעלים; בתחילת המשחק אין בעלים ולכן ערכו `null`. במשבצת פרס או קנס, `amount` הוא סכום הכסף שהמשבצת מוסיפה או מפחיתה. שמות התצוגה יכולים להיות בעברית או באנגלית, אך עליהם להיות יציבים ולהופיע באופן עקבי במצב ובאירועים. הטבלה מציגה שמות אנגליים תקינים ואת הערכים הנדרשים.

## כיצד לוודא שהתרגיל הושלם

בדקו יצירה עם 2, 3 ו-4 שחקנים ואת ארבעת מקרי הקלט הלא תקין שמפורטים למעלה. השוו את כל שמונת שדות המצב, את כל שדות השחקנים ואת כל 16 המשבצות—לא רק את קוד התגובה.
