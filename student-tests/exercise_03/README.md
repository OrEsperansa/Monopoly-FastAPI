# תרגיל 3: שמירת מצב ושליפתו

## מטרת התרגיל

להפוך את השרת למקור האמת של המשחק. לאחר יצירה, אותו מצב נשמר בזיכרון וניתן לשליפה חוזרת ללא שינוי.

## נקודת הקצה החדשה

### `GET /api/game`

הבקשה אינה כוללת גוף. כאשר קיים משחק פעיל, התגובה מחזירה `200` ואת ה-`GameState` המלא ישירות. זהו בדיוק אותו JSON של מצב המשחק, הכולל את שמונת השדות שהוגדרו בתרגיל 2, את כל השחקנים ואת כל 16 המשבצות.

## דרישות שמירת המצב

- שתי בקשות `GET` רצופות מחזירות תוכן זהה למצב שנוצר ב-`POST /api/game`.
- פעולת `GET` היא לקריאה בלבד ואינה משנה כסף, מיקום, בעלות, תור, פעולות זמינות או יומן אירועים.
- ניסיון ליצור משחק לא תקין עדיין מחזיר `422` עם הודעה מתאימה שמסבירה את השגיאה, ואינו מוחק או מחליף משחק תקין שכבר נשמר.
- לאחר יצירה שנכשלה, `GET /api/game` מחזיר את המצב שהיה שמור לפניה.

אם לא נוצר משחק, יש להחזיר `404` עם הודעה מתאימה שמסבירה את השגיאה.

## כיצד לוודא שהתרגיל הושלם

צרו משחק ושמרו את גוף התגובה המלא. שלחו שתי בקשות `GET` והשוו את גופי ה-JSON במלואם. לאחר מכן שלחו יצירה לא תקינה עם שחקן אחד, ודאו `422`, ושלחו שוב `GET` כדי לוודא שהמצב המקורי לא השתנה.
