# תרגיל 5: סיום תור ומעבר בין שחקנים

## מטרת התרגיל

לאפשר לשחקן שסיים לזרוק לסיים את תורו, להעביר את השליטה לשחקן הבא ולהמשיך משחק לאורך מספר תורות.

## נקודת הקצה החדשה

### `POST /api/game/end-turn`

הבקשה אינה כוללת גוף. היא חוקית רק כאשר `end_turn` מופיעה ב-`available_actions`.

תגובה תקינה מחזירה `200` ואת מצב המשחק המעודכן בתוך `state`:

```text
{
  "state": <מצב המשחק המלא לאחר מעבר התור>
}
```

## כללי מעבר התור

- לאחר סיום תור, `current_player_id` עובר לשחקן הבא לפי סדר המזהים.
- לאחר השחקן האחרון חוזרים לשחקן הראשון.
- בתחילת התור החדש `available_actions` היא בדיוק `["roll"]`.
- יש להוסיף ל-`event_log` אירוע באנגלית שמתאר למי עבר התור.
- `last_event` חייב להיות זהה לאירוע האחרון ב-`event_log`.

רצף הפעולות הוא:

```text
roll → available_actions: ["end_turn"]
end-turn → available_actions: ["roll"] אצל השחקן הבא
```

## פעולות שאינן זמינות

אי אפשר לסיים תור לפני זריקה ואי אפשר לזרוק שוב לאחר שכבר נזרקה קובייה. פעולה שאינה זמינה מחזירה `409` עם הודעה מתאימה שמסבירה את השגיאה, ואינה משנה את מצב המשחק.

## מעבר דרך Start

כעת אפשר להריץ מספר תורות ברצף. כאשר שחקן משלים סיבוב ועובר דרך Start, הוא מקבל בדיוק 200 כסף. אירוע התנועה מאותו `roll` חייב להכיל גם את הטקסט המדויק `received 200 for Start` ולהישמר ב-`event_log` שב-`GameState`.

## כיצד לוודא שהתרגיל הושלם

צרו משחק עם שלושה שחקנים, בצעו `roll` ולאחריו `end-turn`, ובדקו שהתור עבר לשחקן 2 וש-`roll` זמינה שוב. המשיכו עד שהתור חוזר לשחקן הראשון. נסו גם `end-turn` לפני זריקה וודאו שמתקבל `409` ללא שינוי מצב. לבסוף הריצו תורות עד שאחד השחקנים עובר דרך Start ובדקו את תוספת הכסף ואת אירוע התנועה.
